# Docker

#### 왜 Docker를 써야하나요?

- 컨테이너는 애플리케이션을 환경에 구애 받지 않고 실행하는 기술이다.
- 운영체제별로 존재하는 복잡한 설치 과정을 겪지 않는다.
- 눈송이 서버 (Snowflake Servers)
  - 서로 모양이 다른 서버들이 존재하는 상황
  - 같은 일을 하는 서버일지라도 서버의 환경이 달라서 장애를 일으킬 수 있으며 그 원인을 파악하기가 힘들다.
  - 서버 업데이트에 대한 내용을 문서화 하더라도 완벽하지 않다.
    - 그 때는 맞고 지금은 틀린 경우
  - 서버의 운영 기록을 코드화하려는 다양한 시도들이 등장
    - 베이그런트 (Vagrant)
    - 셰프(Chef)
    - 퍼핏(Puppet)
    - 앤서블(Ansible)
    - 도커파일(Dockerfile)
- 도커파일 (Dockerfile)
  - 도커 파일 = 서버 운영 기록 코드화
  - 도커 이미지 = 도커 파일 + 실행 시점
  - 도커 컨테이너 = 도커 이미지 + 환경 변수
  - 다른 도구들은 모두 도구를 실행하는 시점에 서버의 상태가 결정되는 데 비해, 도커는 작업자가 그 시점을 미리 정해둘 수 있다. 덕분에 서버를 항상 똑같은 상태로 만들 수 있는 것이다.
  - 도커 파일을 작성하는 것은 TDD와 같다.
- 서버 코드화의 장점
  - 서버 제작 과정에 견고함과 유연성을 더함
  - 다른 이가 만든 서버를 소프트웨어 사용하듯 가져다 쓸 수 있다.
  - 여러 대에 배포할 수 있는 확장성
